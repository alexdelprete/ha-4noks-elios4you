# Release v1.4.0-beta.3

**Release Date:** 2026-09-08

**Type:** Beta release — incremental over v1.4.0-beta.2: host auto-discovery, ZigBee radio

## Overview

The v1.4.0-beta.2 stability soak came back clean — 78 hours of statistics with no anomalies,
including a counter reset carried through correctly. This beta adds the two features that came
out of that testing round, plus documentation for two behaviours every Smart RC owner should
know about. All of it originates from @RickyReds' reports; expected to be the last beta before
1.4.0 stable.

## What's Changed

### Added

- **Host auto-discovery.** The device answers an undocumented discovery protocol on UDP port
  5002 (`Elios4you` → `HELLO <serial>`), discovered by capturing the official app's traffic.
  The add-integration form now broadcasts a probe and pre-fills the host field with the first
  device that answers. Unlike the telnet channel, the UDP endpoint is **non-exclusive** — it
  answers even while the integration is polling — so discovery can never disturb a running
  setup. Manual entry keeps working exactly as before (discovery is best-effort and silent
  when nothing answers).
- **ZigBee radio diagnostics**: two new disabled-by-default diagnostic sensors expose the Red
  Cap's ZigBee **channel** and **PAN ID**. Accessory interference is the most common Smart RC
  complaint, and the channel tells you whether to blame neighbouring WiFi. Enable them from
  the entity registry; on devices without a Red Cap module they simply don't appear.

### Documentation

Two warnings added to the README's Smart RC Troubleshooting section, both verified on real
hardware:

- ⚠️ **Saving accessory settings in the 4-noks app opens the relay — and leaves it open.**
  Even with nothing changed, pressing Save cuts the load and it stays cut until a human turns
  it back on. Don't touch accessory settings while a NAS, PC or freezer hangs off the socket;
  an automation on the Relay binary sensor can alert you.
- ⚠️ **The per-socket operating mode (Manual/Automatic/Timer) can silently revert to
  Automatic**, and the device never reports the mode over the local protocol, so no software
  can detect it. If a socket must not switch on its own, verify its mode in the app
  periodically.

## Installation

**HACS**: integration page → ⋮ → *Redownload* → enable "Show beta versions" → select
1.4.0-beta.3 → restart Home Assistant.

**Manual**: download `4noks_elios4you.zip` from this release, replace the
`config/custom_components/4noks_elios4you/` folder with its contents, and restart
Home Assistant.

## For beta testers

1. **Discovery**: remove and re-add the integration (or just start the add flow and cancel) —
   the host field should arrive pre-filled with your device's IP. Also worth confirming the
   probe really doesn't disturb the running integration.
2. **ZigBee diagnostics**: enable the two new sensors and check the channel/PAN values against
   what you know of your network.
3. Everything from the [beta.2](v1.4.0-beta.2.md) and [beta.1](v1.4.0-beta.1.md) checklists
   still applies.
