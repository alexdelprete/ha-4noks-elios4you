# Release v1.4.2-beta.4

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-4noks-elios4you/v1.4.2-beta.4/total?style=for-the-badge)](https://github.com/alexdelprete/ha-4noks-elios4you/releases/tag/v1.4.2-beta.4)

**Release Date:** 2026-10-20

**Type:** Beta release. Forced aborts now send a TCP reset, as the connection manager was always
designed to do. Incremental notes: only what changed since v1.4.2-beta.3.

## What's Changed

### Fixed

- **Forced aborts now send a TCP reset (RST).** v1.4.2-beta.3 made the connection manager
  reach `transport.abort()`, but `abort()` alone only closes the socket without flushing, and the
  kernel still sends a normal FIN. A production capture after beta.3 confirmed it: 6 forced
  aborts, zero RSTs. The integration has in fact never sent an RST in any version. The socket
  now gets `SO_LINGER` set to on with a zero timeout right before `abort()`, which makes the
  kernel send the RST.

  The RST matters when the device is deaf. After a FIN, the Elios4you keeps the socket slot
  until its telnet task closes its side, and a wedged task never does, so slots leak until the
  device stops accepting connections. An RST is handled by the device's TCP stack alone. In
  healthy operation the device answers a FIN within milliseconds, so nothing changes there
  except the closing packet.

  If the socket is unavailable or refuses the option, the close still happens, as a FIN. Normal
  closes (unload or reload) are unchanged and still send a FIN. Verified on a real socket: the
  peer receives `ConnectionResetError`.
