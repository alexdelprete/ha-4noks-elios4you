# Release v1.4.2-beta.3

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-4noks-elios4you/v1.4.2-beta.3/total?style=for-the-badge)](https://github.com/alexdelprete/ha-4noks-elios4you/releases/tag/v1.4.2-beta.3)

**Release Date:** 2026-10-20

**Type:** Beta release. The connection manager now reaches the socket transport on forced aborts.
Incremental notes: only what changed since v1.4.2-beta.2.

> **Correction (added after release):** these notes originally said forced aborts "now really
> send a TCP reset". That was wrong. This release makes the code reach `transport.abort()`, but
> `abort()` alone still closes with a normal FIN, as a production capture after this release
> showed (6 aborts, 0 RSTs). The RST is actually sent from
> [v1.4.2-beta.4](https://github.com/alexdelprete/ha-4noks-elios4you/releases/tag/v1.4.2-beta.4),
> which sets `SO_LINGER` to 0 before the abort. On the wire, this release behaves like
> v1.4.2-beta.2.

## What's Changed

### Fixed

- **Forced aborts never reached the socket transport.** When a command times out or the socket fails,
  the connection manager is meant to drop the connection with an RST. An RST frees the device's
  socket slot at once, while a normal close (FIN) can leave the slot occupied on the Elios4you's
  small TCP stack. The code looked the transport up with `writer.get_extra_info("transport")`,
  which returns `None` on telnetlib3 writers, so every forced abort fell back to a normal FIN
  close.
  - A packet capture on a production install confirmed it: 18 forced aborts, zero RSTs.
  - The transport is now taken from the writer's `transport` attribute. (As the correction above
    explains, reaching `abort()` turned out not to be enough for an RST.)
  - The same dead lookup had also disabled the "transport is closing" check before reusing a
    connection. That check works again too.
  - The unit tests had missed it because their fake writer returned the transport from
    `get_extra_info`. They now mirror real telnetlib3, and a regression test uses a real
    telnetlib3 writer.
