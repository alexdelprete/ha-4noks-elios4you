## What's Changed

### Fixed

- **Forced aborts never sent a TCP reset (RST).** When a command times out or the socket fails,
  the connection manager is meant to drop the connection with an RST. An RST frees the device's
  socket slot at once, while a normal close (FIN) can leave the slot occupied on the Elios4you's
  small TCP stack. The code looked the transport up with `writer.get_extra_info("transport")`,
  which returns `None` on telnetlib3 writers, so every forced abort fell back to a normal FIN
  close.
  - A packet capture on a production install confirmed it: 18 forced aborts, zero RSTs.
  - The transport is now taken from the writer's `transport` attribute.
  - The same dead lookup had also disabled the "transport is closing" check before reusing a
    connection. That check works again too.
  - The unit tests had missed it because their fake writer returned the transport from
    `get_extra_info`. They now mirror real telnetlib3, and a regression test uses a real
    telnetlib3 writer.
